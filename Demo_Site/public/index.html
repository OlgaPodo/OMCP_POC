Option 1: Examples Embedded Inside @Agent.Prompts

Examples (utterance & OData request pairs) are packaged directly inside the prompt record in CSDL metadata.

  • Unified Semantic Model: The prompt encapsulates the name, description, parameters, template messages, AND example utterances.
  • Direct MCP Alignment: Maps 1:1 to MCP prompts/list and prompts/get without needing external cross-reference lookups.
  • Zero-Shot Semantic Routing: LLM gateways and agents can vectorize the Examples field as a retrieval index to pick the right prompt.
"Sales.Container": {
  "@Agent.Prompts": [{
    "Name": "answer_bi_question",
    "Arguments": [{ "Name": "question", "Required": true }],
    "Messages": [...],
    "Examples": [{
      "Utterance": "Which invoices are overdue?",
      "Request": "Invoices?$filter=DueDate lt now()"
    }]
  }]
}
Alternative Considered

Option 2: Separate @Agent.ExampleQueries Term

Prompts and example queries live as distinct terms on the entity set/container.

  • Separates general query examples from structured prompt templates.
  • Requires gateways to perform an additional join step between @Agent.Prompts and @Agent.ExampleQueries.
  • Does not provide a unified payload when exporting to MCP prompts/list.
"Sales.Container/Invoices": {
  "@Agent.ExampleQueries": [{
    "Utterance": "Which Contoso invoices are overdue?",
    "Request": "Invoices?$filter=Customer/Name eq 'Contoso' and DueDate lt now()"
  }]
}

Addressing Concern 1: The Meaning of MCP Prompts

⚠️ "The meaning of MCP prompts was unclear. The proposal described prompts as a search index, but the MCP specification presents them more like reusable templates."
MCP Specification View

Reusable Parameterized Templates

In the official Model Context Protocol specification, prompts are user- or agent-controlled slash-command-style templates:

  • Interactive workflows: Invoked when a user selects a template (e.g., /whom_olga_reports_to) or an agent executes a macro.
  • Message Generators: Accept arguments (e.g., userName="Olga") and expand into a sequence of structured prompt messages (role: "user", content: { text: "..." }).
  • Tool / Resource links: Can embed explicit context references such as {tool:user_profile} or {resource:users://me}.
OData TC / Enterprise View

Semantic Retrieval Index (Catalog)

For large enterprise APIs like Microsoft Graph (with 1,000+ endpoints), exposing individual tools saturates LLM context windows:

  • Context Window Constraint: Tool selection becomes unreliable beyond ~120 tools.
  • Work IQ & Graph Copilot Pattern: Instead of 1,000 tools, services use a catalog of curated natural-language query examples to index API calls.
  • Search-then-Query: The agent matches user utterance (e.g. "Who is Olga's manager?") against example query embeddings to select the appropriate tool or API request.
✨

How Option 1 Reconciles Both: The Dual-Role Prompt

Option 1 bridges this gap by unifying both requirements into a single CSDL annotation:

1

At Execution Time (MCP Specification Role):

The prompt serves as a strictly compliant MCP template via prompts/get, returning parameterized messages and tool references.

2

At Discovery Time (Search Index Role):

The gateway uses the Examples array as vector embeddings or text search candidates. When a user asks an arbitrary question, the agent searches the prompt catalog first to select the prompt.
