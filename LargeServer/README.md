# Large Microsoft Graph HTTP MCP 2.0 Server (`C:\MCP\LargeServer`)

Runs the MCP 2.0 (`2026-07-28`) server generated by `CsdlToMcpTransformer` from
`Server_Large_WithExamples.csdl`, exposing tools, resources, prompts, and
entity/operation examples across Microsoft 365 workloads:

- **Entities (`EntityType` / `EntitySet` / `Singleton`)**: `User` (`users`, `me`), `Group` (`groups`), `Drive` (`drives`), `DriveItem` (`driveItems`), `Team` (`teams`), `Channel` (`channels`), `Chat` (`chats`), `ChatMessage` (`chatMessages`), `TodoTaskList` (`todoLists`), `TodoTask` (`todoTasks`)
- **Bound OData Operations (`Function` / `Action`)**: `searchDriveItems`, `recentDriveItems`, `deltaChannelMessages`, `sendChannelMessage`, `completeTodoTask`
- **Container Prompts (`@Agent.Prompts`)**: 22 single-resource and cross-workload M365 prompts
- **Entity & Operation Examples (`@Agent.Examples`)**: 28 annotated examples across entities, entity sets, singletons, functions, and actions
- **Endpoint**: `http://localhost:3003/`

MCP tools and resources share generated `ODataRequestBinding` metadata.
`ResourceBinding.RequestBinding` describes the OData request executed by a resource
read; it does not represent an MCP tool invocation. Matching examples are included
in the returned resource content, not in resource discovery.

All CSDL parsing, binding/schema generation, resource-pattern construction,
example association, and discovery/catalog inference belong to the transformer.
This project contains only generated metadata and runtime code for serving MCP
and diagnostic APIs, rendering prompts, validating inputs, and executing requests.
It neither reads CSDL files nor depends on the transformer or ODL at runtime.

## Class responsibilities

| Class or type group | Responsibility |
|---|---|
| [Program bootstrap](Program.cs) | Configures dependency injection, MCP handlers, and diagnostic HTTP endpoints. |
| [GeneratedModel](Csdl/GeneratedModel.cs) | Holds transformer-emitted runtime metadata; does not generate it at runtime. |
| [CsdlProvider and binding records](Csdl/CsdlProvider.cs) | Expose generated metadata and render prompt templates using supplied arguments. |
| [CsdlMcpProjection](Csdl/CsdlMcpProjection.cs) | Handles discovery, tool calls, and resource reads; constructs requests and serializes results. |
| [EdmJsonSchema](Csdl/EdmJsonSchema.cs) | Validates runtime values, parses resource keys, and formats OData literals. |
| [IODataClientService, ODataClientService, and ODataTrace](Services/ODataClientService.cs) | Define and implement in-process request execution, normalize JSON results, and record execution timing. |
| [GeneratedGraphExecutor](Services/GeneratedGraphExecutor.cs) | Dispatches bindings to direct or workload-specific Graph client operations. |
| [GraphClientService](Services/GraphClientService.cs) | Acquires tokens, sends Graph HTTP requests, records correlated traces, and provides existing offline fallbacks. |
| [Graph model classes](Models/GraphModels.cs) | Transfer workload data, typed collection responses, and trace records; each class has its own responsibility summary. |
| [Transformer Program](../CsdlToMcpTransformer/Program.cs) | Parses and validates CSDL and writes a standalone server project. |
| [StaticModelGenerator](../CsdlToMcpTransformer/StaticModelGenerator.cs) | Computes bindings, links, schemas, discovery, catalogs, and diagnostics at generation time. |

Responsibility summaries are maintained in the transformer templates and emitted
source so they survive regeneration.

## Call sequence: `resources/read` for `me`

After MCP initialization, the client sends this JSON-RPC request to the MCP endpoint:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "resources/read",
  "params": {
    "uri": "odata://Microsoft.Graph.GraphService/me"
  }
}
```

The successful live-request path is:

```mermaid
sequenceDiagram
    participant Client as MCP client
    participant Host as MCP HTTP handler
    participant Projection as CsdlMcpProjection
    participant Metadata as CsdlProvider / GeneratedModel
    participant OData as ODataClientService
    participant Executor as GeneratedGraphExecutor
    participant Graph as GraphClientService
    participant API as Microsoft Graph
    Client->>Host: resources/read(uri=odata://Microsoft.Graph.GraphService/me)
    Host->>Projection: ReadResourceAsync(request)
    Projection->>Metadata: GetProjectedResources()
    Metadata-->>Projection: Prelinked get_me resource binding
    Note over Projection: Match fixed URI; arguments are empty
    Projection->>Projection: ExecuteAsync(binding, arguments)
    Projection->>OData: SendAsync(binding, GET, "me")
    OData->>Executor: ExecuteAsync(binding, GET, "me")
    Executor->>Graph: ExecuteODataQueryAsync("me")
    Graph->>Graph: GetAccessTokenAsync()
    Graph->>API: GET https://graph.microsoft.com/v1.0/me
    API-->>Graph: User JSON
    Graph-->>Executor: JsonElement
    Executor-->>OData: Result
    OData-->>Projection: Normalized JsonElement
    Projection->>Metadata: GetExamplesFor(binding)
    Metadata-->>Projection: Precomputed binding.Examples
    Projection->>Projection: SerializeResponse(binding, execution)
    Projection-->>Host: ReadResourceResult
    Host-->>Client: contents with URI, application/json, and JSON text
```

`me` is a singleton, so no entity key is extracted and `ParseKey` is not called.
Its `get_me` binding uses `GraphExecutionKind.Direct`; no `tools/call` request or
`CallToolAsync` invocation occurs. The returned JSON text contains `method`,
`odataQuery`, `entitySet`, `data`, and the three preassociated `me`/user examples.
Those examples are returned as guidance, not executed.

If authentication or the initial live request fails, the existing fallback path is
`ExecuteMockODataQueryAsync("me")` -> `GetMeAsync()` -> `GetUserProfileAsync("me")`.
That profile path can retry Graph requests and ultimately use mock data. It is not
the normal successful `GET /me` path shown above.
